GraphQL

The full v2 read surface is also available as GraphQL at POST /v2/graphql — one endpoint, exactly the fields you ask for, multiple resources in a single round trip.

Playground: open /v2/graphql in a browser for the built-in GraphiQL IDE (it loads GraphiQL from a CDN, so the API ships no extra payload for it). Introspection is enabled, so any GraphQL client can discover the schema.

Quick start

curl -X POST https://gplayapiv2.fly.dev/v2/graphql \
  -H 'content-type: application/json' \
  -d '{"query":"{ app(appId: \"com.instagram.android\") { title score installs developer { devId } } }"}'

Field selection & app shape

The App type mirrors the REST app object, including the absolute deep links (url, permissions, similar, reviews, datasafety, developer.url, categories) that the REST surface embeds. GraphQL selection sets are the native equivalent of the REST ?fields= projection — only requested fields travel over the wire.

Errors

GraphQL-over-HTTP answers 200 with an errors array even for upstream failures; the REST problem taxonomy travels in extensions: 

{
  "errors": [{
    "message": "App not found (404)",
    "path": ["app"],
    "extensions": {
      "httpStatus": 404,
      "code": "HTTP_404",
      "type": "https://api.google-play-api.dev/problems/not-found"
    }
  }]
}

extensions.retryAfter is present for rate-limit (429) and upstream-timeout (504) errors, matching the REST Retry-After header. Request-level problems — malformed documents or queries exceeding the depth limit — return a real HTTP 400.

Depth limit

Queries are capped at 10 levels of nested field selection (override with the GRAPHQL_MAX_DEPTH environment variable). Over-deep queries are rejected before execution with extensions.code = "GRAPHQL_MAX_DEPTH".

Local queries

country/lang arguments behave like the REST query params: they default to the server configuration, accept ISO-3166-1 alpha-2 codes and BCP-47 tags, and invalid values produce the 400 error shown above.
