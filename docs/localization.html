Localization: country & lang

Every request targets a Google Play storefront. Two parameters control which store and which language you see: country and lang.

Single source of truth

Defaults are resolved in one place — the router middleware in lib/index.js — using constants from lib/constants.js. There is no per-route override logic.

LayerValueNotes
Query param?country=IN&lang=taHighest priority. Validated per request.
Env overrideCOUNTRY_OF_QUERY / LANG_OF_QUERYServer-wide default when no query param is given.
Code constantDEFAULT_COUNTRY='US' / DEFAULT_LANG='en'Fallback when env is unset.

Validation

  • country — ISO 3166-1 alpha-2, case-insensitive. Normalized to uppercase before use. Invalid codes return 400 with application/problem+json on /v2.
  • lang — ISO 639-1, case-insensitive. Normalized to lowercase. Invalid codes return 400.

Country / lang matrix

The scraper passes country and lang directly to the Play Store batchexecute endpoint. Any valid ISO pair is accepted — the API does not maintain a hardcoded allowlist. Common combinations:

countrylangStorefront
USenUnited States (default)
INenIndia, English
INtaIndia, Tamil
INhiIndia, Hindi
GBenUnited Kingdom
DEdeGermany
JPjaJapan
BRptBrazil

Note: not every app is available in every storefront. A valid request may still return 404 App not found if the app is geo-restricted.

Examples

# Default (US / en)
curl "https://gplayapiv2.fly.dev/v2/apps/com.instagram.android"

# Indian storefront, Tamil UI
curl "https://gplayapiv2.fly.dev/v2/apps/com.instagram.android?country=IN&lang=ta"

# Invalid country → 400 problem+json
curl "https://gplayapiv2.fly.dev/v2/apps/com.instagram.android?country=XX"

Environment configuration

# .env
COUNTRY_OF_QUERY=IN
LANG_OF_QUERY=en

The gplayapiv2 verification deployment sets COUNTRY_OF_QUERY=IN to match the primary audience. Production (main) uses the code default (US / en) unless overridden.
